Historical temporary receipts marked unavailable below cannot be inspected in the restored October 19 checkout; see the [current checkpoint](platform-test-current.md) for the evidence qualification and current certification status.

This partial inventory records inspected assertions, not a claim that every listed test passed in the current campaign.
Rows combine historical inspection with subsequent campaign repairs; use each row's evidence and the current checkpoint to distinguish completed work from remaining gaps.
The [campaign plan](platform-test-plan.md) owns priority order and the systematic per-feature completion requirements; all in-scope gaps remain obligations after the main GUI paths.
Every row declares its stable feature ID directly; that ID is the sole mapping key to the [obligation dashboard](platform-test-dashboard.md), while labels and row positions are descriptive only.
The `Scenario contracts` cell records all five dashboard dimensions with the dashboard state: applicable cells delegate to the row's named behavior and evidence/gap prose, while each `N` repeats its concise non-applicability reason.
It covers local GUI editing and authoring; workflow lifecycle, recursive interfaces, results, integrations, and execution have complementary campaign inventories.
HPC, Parsl, distributed engines, remote execution, and parallel execution behavior are excluded.
Browser automation remains an opt-in lane called after substantial changes, using the authoritative commands in [Testing](../testing.md).

In the tables, browser paths are relative to `frontend/tests/e2e`, frontend paths to `frontend/src`, and backend paths to `backend/tests`.
Quoted titles are exact test selectors usable with `scripts/test focus e2e <file> --grep '<title>'` or `scripts/test focus unit <file> -t '<title>'`.
Backend method names are searchable selectors usable with `scripts/test focus backend <file> -k '<name>'`.
An API-seeded browser fixture proves the browser behavior asserted after setup; it does not prove the equivalent setup action works through the GUI.
